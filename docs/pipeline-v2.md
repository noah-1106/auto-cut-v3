# auto-cut 管线 v2 立项设计
## 从"会话内急救"到"Agent 全自动流水线"
### 2026-09-15 · 维护团队 · 状态：✅ 已全部落地（六件事验收完毕，新素材包冷启动零急救实锤）——本文件保留为设计史料，运行态以 README 管线全景表为准

---

## §0 核心目标（项目存在的理由）

**Agent 自动处理时，可以从原始素材毫无障碍地进展到成片。**

- 人是规则制定者 + 终审，不是质检员，不是流水线卡点
- 检验标准：换一批新素材包，从导入到成片，**全程是否需要会话内人工急救**——需要，就是管线没到位
- 对照物：剪映里人是操作员；这里 Agent 是操作员，人定规则和终审

## §1 五轮个案修复暴露的管线缺口（教训清单）

早期真实项目五个版本的修复全部发生在会话层（AI 手工急救），没有一层沉淀为管线环节：

| # | 教训 | 该成为的环节 |
|---|---|---|
| 1 | b7 三遍 take 切成缝合怪——dup/retake 检测函数存在但从未被调用（档案 defects=[]） | 缺陷检测环节 |
| 2 | b3 素材 ASR 时间戳漂移 3s 导致字幕错位——时间戳被全链当真值消费 | 时间源切换（VAD 物理测量） |
| 3 | b1 "三二一走"拍摄口令被播进出片——素材词轨黑区（ASR 漏转写） | 黑区检测（能量有语音、词轨无文本→掐） |
| 4 | b7 尾部 2.3s 静音+离麦嘟囔——音频结构（静音洞/音量骤变）无环节看一眼 | 听觉维度 QC |
| 5 | 掐头掐尾、分段解密、VAD 词轨全是会话内手工——dubgate/vadwords 是散脚本未挂流程 | 裁剪/词轨自动化环节 |

**根因：管线是"能力散件"不是"验证闭环"。每个环节对上游格式负责，没有环节对物理真值负责。**

## §2 管线全景（v2 目标态）

```
素材包导入
  → ①转写（自动）        产物: pack.json（词轨+文本）
  → ②理解（自动）        产物: digest（场景/人物/画面质量）
  → ③缺陷检测（自动）    产物: defects 台账（新增环节）
  → ④缺陷处置（自动）    产物: disposition 日志（新增环节，按 §4 规则执行）
  → ⑤起草（自动）        产物: 故事线
  → ⑥裁剪（自动）        产物: dub 音频 + 验证报告（dubfit.py，新增环节）
  → ⑦词轨（自动）        产物: VAD 词轨（vadwords.py 挂渲染前置）
  → ⑧渲染（自动）        产物: 成片
  → ⑨门禁（自动）        产物: 门禁报告（dubgate+G1文本+G2t时间+听觉QC，不过闸不出片）
  → 成片交付（附处置日志+门禁报告）
```

**每环节三问：产物是什么文件？自动还是手工？下游谁消费？——手工环节为零。**

## §3 人机分工（v2 修正版）

| 层 | 谁 | 内容 |
|---|---|---|
| 全自动层（默认态） | Agent | ①-⑨ 全链自动，全程无人 |
| 规则层 | 人 | 改 config/defects-policy.json 的阈值和策略——一次改动全项目生效，不逐条确认 |
| 终审层 | 人 | 成片抽检（可选）；不满意的改故事线重渲；批量场景可以不看 |

**设计原则：Agent 的判断置信度足够高时（量化判据实锤），不设人工卡点。**
人工介入是可选加速器，不是必需关卡。

## §4 缺陷处置规则（config/defects-policy.json 初版）

| 缺陷类型 | 检测判据（量化） | 自动处置 |
|---|---|---|
| retake-suspect | dup 指纹：同文本段重复出现 | 自动选内容完整的净 take，剪废段 |
| 静音洞 | VAD 静音段 >1.5s 且处于句中 | 剪除 + 词轨平移 |
| 黑区 | 能量包络有语音、词轨无文本（口令/嘟囔） | 自动掐掉 |
| 音量骤变 | 相邻段响度差 >8dB | 增益补偿到目标响度；补偿后仍异常则剪除 |
| 句首吞字 | dubgate D1：裁出音频首词≠story 首字 | 自动回退裁点重裁（静音谷重定位） |
| 时间戳漂移 | 词轨 vs 波形对账超差 | 弃用 ASR 时间戳，VAD 物理测量铺排 |

所有处置写 disposition 日志（剪了什么/依据/影响哪些幕），**留痕可审计，不需事前批准**。

## §5 与剪映的本质区别

剪映：人是操作员（选材/剪点/字幕/音乐全手动），工具是手。
本项目：Agent 是操作员（全链自动+按规则决策），人是规则制定者和终审。
**价值主张：批量生产场景下，人一个项目看一次片，甚至不看。**

## §6 改造工作清单（按依赖排序）

1. **defects 台账**：dossier.detect_takes 等散件挂进转写/理解后流程，产物落库+前端面板读真数据
2. **defects-policy.json**：§4 规则编码 + 处置执行器（disposition engine）
3. **dubfit.py**：包络定位→掐头掐尾→ASR 闭环，固化裁剪环节（吸收 dubgate）
4. **vadwords 挂载**：渲染前置自动跑，显式词轨唯一来源，废除 ASR 时间戳消费链
5. **门禁挂载**：dubgate+G1+G2t+听觉 QC 全挂 render 流程，exit 1 即拦截
6. **QC 听觉维度**：静音洞/音量骤变/非预期语音自动检测规则入 qc.py

依赖关系：1→2→3→5；4、6 独立可并行。
预计：每项 0.5-1 天级工作量，串行 3-4 天出 v2 管线。

## §7 验收标准

用一个全新素材包（非该早期项目）做冷启动测试：
- 全程零会话内人工急救（违例即管线缺口，记录返工）
- 成片门禁全绿（文本/时间/听觉三域）
- 处置日志完整可审计
- 人工介入总时长 <10 分钟（仅终审看片）
